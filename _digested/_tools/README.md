# _tools — 文档自检工具

## `check_anchors.py`

把 `_digested/` 与 `_faq_on_digested/` 里所有 `文件:行号` 形式的锚点解析到工作树，检查两种机械性失效：

- **NOFILE**：全树找不到该文件名的源文件（文件被删或改名）
- **OOB**：文件存在但比引用行号短（文件被大幅改写／删减）
- **BADPATH**：全文任何一个文件都不以该锚点的**目录前缀**结尾（例如 `parse/parsers/registry.py`——`registry.py` 确实存在，但在 `parse/` 下，不在 `parse/parsers/` 下）。**这一项是 2026-10-19 补的**：此前只比对 basename，于是"文件对、目录错"的锚点全部漏检，包括本套文档自己写出来的一个。

```bash
python3 _digested/_tools/check_anchors.py           # 报告
python3 _digested/_tools/check_anchors.py --strict  # 有发现则非零退出
```

**它是"边界检查"不是"语义检查"**——通过的锚点仍可能指错东西。它只负责拦住锚点腐烂里最廉价、也最容易悄悄积累的那一半。

## 墓碑约定

指向**已在 upstream 删除**的机制的锚点是有价值的（它记录了"这里曾经有什么"），不该被当成错误。在同一行写上下列任一标记即可让检查器跳过：

`~~`（删除线）、`旧基线`、`已删除`、`被删`、`不存在`、`旧锚点`、`已缩到`、`旧分支`

## 它看不见什么（重要）

1. **`符号(:NN)` 裸行号**：`mcp_endpoint.py` 里有一整段写成 `` `find`(:249) ``，没有文件名，检查器完全看不到。该段在 `v0.5.0` 已整体漂移（`:249` 实际应是 `:449`），是靠手工复核才发现的。**取证请一律写 `文件:行号`。**
2. **语义**：锚点行号对、但那一行讲的是别的事——检查器无从判断。
3. **"某层没变"类断言**：这类句子不指向任何一行代码，却是本套文档里代价最高的一类错误（见 `_change_log/0003`）。
