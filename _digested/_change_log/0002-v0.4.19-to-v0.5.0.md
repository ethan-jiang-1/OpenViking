## 一、P0：结论级反转

### 1. 检索从"两级递归"改为"全局召回 + 一次精排"

`_digested/core/03-retrieval-two-levels.md`（现已更名为 `03-retrieval-global-recall.md`）整篇的立论**作废**。

| 项 | v0.4.19（0001 基线） | v0.5.0 |
|---|---|---|
| 结构 | THINKING = 全局找 L0/L1 目录命中 → 逐层递归（优先队列）→ 父级分数传播 | 每个 TypedQuery **一次全局向量召回**，THINKING 额外对候选做一次 rerank |
| 递归符号 | `_recursive_search`、`dir_queue`（heapq）、`MAX_CONVERGENCE_ROUNDS=3`、`MAX_PARALLEL_CHILD_SEARCHES=4` | **全部删除**（全仓零命中） |
| 配置项 | `retrieval.score_propagation_alpha`、`retrieval.hotness_alpha` | **两个都删除**（`openviking_cli/utils/config/retrieval_config.py` 只剩 `enable_intent`、`recall_intent_timeout_s`、`recall_rewrite_timeout_s`） |
| 热度加权 | THINKING 下 `final = (1-α)·semantic + α·hotness` 参与打分 | 取消。`hotness_score()` 的唯一消费者变成 `storage/stats_aggregator.py:96`（统计，不进检索） |
| find vs search 差异 | QUICK 扁平 / THINKING 递归 | 只剩**是否精排**：`mode` 未指定时，配了 rerank client 就是 THINKING，否则 QUICK（`hierarchical_retriever.py:122-126`） |

证据：`openviking/retrieve/hierarchical_retriever.py:4`（"Global vector retrieval with optional reranking of the recalled candidates"）、`:54` `RERANK_CANDIDATE_MULTIPLIER = 2`、`:94-107`（`retrieve()` 整段 docstring）、`:183`（`search_limit = limit * 2 if use_rerank else limit`）；删除提交 `69e71e4ff`（"移除逐层检索、递归 rerank 和父级分数传播"）与 `00490c93a`（"移除热度加权及其配置"）。

**两个必须显式反转的旧结论**：

- 0001 的"已知问题"写：*"`find` 固定 QUICK、纯扁平向量检索、**不做目录递归**；'向量先找候选目录再目录内探索'只存在于 `search`（THINKING 模式）"*——**前半句仍成立，后半句作废**：v0.5.0 里 `search` 也不再递归。反转后的正确说法是"**两种模式都不递归**"。
- `core/03:45-49` 曾把根 README 的 *"Vector search finds candidate directories, then explores their contents"* 当作 upstream 自述的偏差来纠正——**这个偏差已被 upstream 自己修掉**：`README.md:60` 现在是 *"Search a directory, not the whole index… `find` runs a query directly; `search` plans retrieval from session context"*。该纠正条目作废。（搬迁到 v0.5.0 之后，工作树里的 `README.md:60` 也是新句了，旧句已随源码更新消失。）

**新增能力**：`search_type` 增加 `"keywords"`（BM25 全文），与 `"semantic"` 并列（`openviking/core/retrieval_types.py:7`；仅 volcengine/vikingdb 后端、图像查询拒绝）。

## 二、P1：行为性变更

### 5. 新运行层：`openviking_gateway/`

v0.5.0 出现第四个运行层（Python ASGI，独立进程，7.0k 行）：

- 入口 `openviking-gateway`（`pyproject.toml:216`），默认端口 **1935**，**beta**。
- 作用：任何**只改 base_url + API key** 的模型客户端都能拿到 OpenViking 记忆——每轮自动召回、模型可调用 OpenViking 工具（网关自己执行）、会话回存并压缩。
- 支持三套协议：Anthropic Messages / OpenAI Chat Completions / OpenAI Responses，均原样转发到配置的 upstream。
- **与内核零代码耦合**：`grep -c "from openviking" openviking_gateway` = 0，只走 HTTP 公共 API；服务端只在 `/api/v1/admin/gateway/{path}` 做管理代理。
- 状态自持：两个加密 SQLite 文件；不依赖服务端也可继续对话（无记忆）。

这使"六种接入形态"变成**七种**。

### 6. pi 扩展的工具面改名（breaking）

pi extension 0.4.0 删掉自己那 7 个手写 `viking_*` REST 工具，改为经官方 MCP 客户端透传服务端 `tools/list`，工具名一律 `openviking_<tool>`（`viking_search` → `openviking_search`），**无别名期**。pi 的 `--tools` / `--exclude-tools` 按精确名匹配，旧 allowlist 会**静默丢工具**。

`integration/01:71` 的"pi = 原生 extension（7 × `viking_*`）+ compaction 接管"整行作废。

### 7. Watch API 迁移（breaking）

带 `watch_interval > 0` 的重复导入**不再更新或重新激活**已有 Watch；暂停中的原生 Watch 保持独占所有权；目标不兼容复用返回 `409 Conflict`；URI 查找到多个可访问 Watch 也返回 409。更新脚本改为 `PATCH /api/v1/watches/{task_id}`。Connector Watch 可共享目标，重试**不再幂等**。

### 8. `POST /api/v1/sessions/{session_id}/used` 删除

无替代、无 changelog 记录。依赖 `used()` 记账的集成会静默失去数据。

### 9. 安装器与 CLI 分发

- 统一安装器 `curl -fsSL https://openviking.ai/install | bash`：覆盖 Claude Code、Codex、Cursor、TRAE/TRAE CN、TraeCode CLI 2.0、ZCode、**Kimi Code**、OpenCode、pi、DSH（`examples/memory-plugin-shared/install.sh:3-5`）。
- **CLI 默认安装**：安装器现在默认从 npm 装 `ov`（`install.sh:10-11,229`；npm 包 `@openviking/cli` + 按平台的可选依赖）。
- 插件配置接缝重构：所有 knob 收敛到**单一声明** `examples/memory-plugin-shared/lib/config-schema.mjs`（`KNOBS`/`CAPABILITIES`/`HARNESS_KEYS`），由 dsh / codex / pi / opencode 共享 `buildPluginConfig()`；生成副本由 `pr.yml:43-55` 硬门禁守住（`git diff --exit-code`）。

### 10. Workspace peer 改为从 git 推导

编码 agent 插件的 workspace peer 默认 `peer.source: "git"`（仓库规范化 `origin` URL，回退到仓库根路径），同一仓库的所有 clone/worktree/子目录共用一个 peer，fork 保留自己的。**非 git 目录不再有 peer**，记忆落到用户级空间；要独立可建 `.openviking/config.json` 写 `{"version":1,"peer":{"id":"my-project"}}`。`OPENVIKING_PEER_SOURCE=cwd` 恢复旧行为。

### 11. 账号级运行时配置系统

新包 `openviking/config/`：集群配置（`OpenVikingConfig`）与账号配置（`AccountConfig`）两个独立 Pydantic 作用域，三态 PATCH 合并（缺失 / null / 值）、按作用域发布、新旧 diff、消费者通知。对应 `/api/v1/admin/configuration` 与 `/api/v1/admin/accounts/{account_id}/configuration`；旧的 `/settings` 端点标 `deprecated=True`。
